# Support

## Getting Help

If you have a question about the repository structure, documentation format, or
how to add a new DSA problem, start by checking:

- [README.md](README.md)
- [CLAUDE.md](CLAUDE.md)
- [CONTRIBUTING.md](CONTRIBUTING.md)

## When to Open an Issue

Open an issue when:

- a solution appears incorrect
- a markdown explanation is misleading or incomplete
- the repository structure or workflow needs improvement
- a standard file is missing or outdated

## When Not to Open an Issue

Please avoid opening issues for:

- personal coding homework requests
- general interview coaching unrelated to the repo
- private support requests that do not affect the project itself

## Best Way to Ask

When reporting a problem or asking for clarification, include:

- the file or problem number involved
- what you expected
- what you observed
- any reproduction steps or example input
